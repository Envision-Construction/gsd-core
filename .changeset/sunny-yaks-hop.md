**A second project in an initialized repository no longer overwrites or appends to the first** — `/gsd-new-project` in a repository that already has a GSD project now creates and selects `.planning/<slug>/` beside it instead of refusing, and `/gsd-do` routes a separate initiative there instead of into the current roadmap. Commands that take arguments accept `--project <name>`, `project set|get|list` keeps the choice for the session (subagents and linked worktrees included, even when the project's directory is gitignored), and `/gsd-progress` reports it. Workflows, agents, references, command bodies and templates now name the project's ROADMAP, STATE, REQUIREMENTS, PROJECT, config, research, phases, milestones, quick tasks, audits and pause handoffs through their resolved paths (`init` fields or the new `planning dir` query) instead of literal root paths, workstream commands and selections are per project, and the retrospective and milestone summaries are kept per project; a lint over those files keeps root literals out. `GSD_PROJECT` now follows the `--project` name rules (no reserved GSD directory names such as `phases` or `research`).
